# Cutscene playback on Wine

Story cutscenes are MP4 files requested by the game's Unity `VideoPlayer` from
`https://cloud.nikke-kr.com/media/...` and decoded through Wine's Media
Foundation. On a stock Proton/Wine prefix they fail with a black screen (and
`WindowsVideoMedia error 0x...` in the player log). The server side needs no
patch: upstream already serves `/media/...` from its cache and falls back to
downloading from the CDN.

This was fixed on Linux by four independent changes. All four are needed for
offline playback; the first three are needed for any playback.

| # | Piece | Why |
|---|---|---|
| 1 | Wine 11.22 | Wine 11.0 returns `0x80070057` (`E_INVALIDARG`) from `MFCreateSourceReaderFromURL` |
| 2 | `Urlmon` scheme handler | Proton/GE prefixes map `http:`/`https:` to winedmo, which cannot open the URL |
| 3 | CA trust + CDN hostname routed to the local server | The local server uses a self-signed cert; wininet checks the chain and the hostname |
| 4 | Media cache | Uncached files 404 when offline, which shows as a black/stalled video |

These instructions are for the EpinelPS Linux launcher layout. They are
machine-setup notes, not server code, and are not needed on Windows.

## 1. Use Wine 11.22

Any 11.22-or-newer build works. The launcher reads the Wine binary from
`$DATA/wine-path` (`$DATA` defaults to `~/.local/share/EpinelPS`):

```bash
echo /path/to/wine-11.22/bin/wine > ~/.local/share/EpinelPS/wine-path
```

Upgrading the prefix in place is fine (Wine upgrades a prefix when it starts);
back it up first. Keep the old `wine-path` value for rollback.

Sanity check outside the game, using the probe in `tools/mfprobe/` (build with
the same Wine's `winegcc`, see below):

```bash
WINEPREFIX=/path/to/prefix WINELOADER=/path/to/wine \
  wine tools/mfprobe/mfprobe.exe https://cloud.nikke-kr.com/media/ch01_end_en.mp4
```

A working setup prints `MFCreateSourceReaderFromURL: 0x0` and a decoded video
subtype.

## 2. Register Wine's Urlmon scheme handler

Stock Proton/GE-Proton prefixes contain:

```
[Software\Microsoft\Windows Media Foundation\SchemeHandlers\http:]
"{587eeb6a-7336-4ebd-a4f2-91c948de622c}"="winedmo Scheme Handler"
```

Replace it with Wine's Urlmon handler in both the 64-bit and `Wow6432Node`
(32-bit) views. Save this as `scheme-handlers.reg`:

```
Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\Software\Microsoft\Windows Media Foundation\SchemeHandlers\http:]
"{9ec4b4f9-3029-45ad-947b-344de2a249e2}"="Urlmon Scheme Handler"

[HKEY_LOCAL_MACHINE\Software\Microsoft\Windows Media Foundation\SchemeHandlers\https:]
"{9ec4b4f9-3029-45ad-947b-344de2a249e2}"="Urlmon Scheme Handler"

[HKEY_LOCAL_MACHINE\Software\Wow6432Node\Microsoft\Windows Media Foundation\SchemeHandlers\http:]
"{9ec4b4f9-3029-45ad-947b-344de2a249e2}"="Urlmon Scheme Handler"

[HKEY_LOCAL_MACHINE\Software\Wow6432Node\Microsoft\Windows Media Foundation\SchemeHandlers\https:]
"{9ec4b4f9-3029-45ad-947b-344de2a249e2}"="Urlmon Scheme Handler"
```

A ready-to-use copy is in `tools/wine-shims/scheme-handlers.reg`. With no Wine
process running for that prefix:

```bash
WINEPREFIX=/path/to/prefix wineserver -k
WINEPREFIX=/path/to/prefix wine reg import tools/wine-shims/scheme-handlers.reg
```

## 3. Trust the CA and route the CDN hostname to the local server

The local server listens on 443 with `site.pfx`, generated by upstream's
`generate_ssl_cert.sh`. That certificate is issued by a private CA (the script
calls it `myCA.pem`; the copy shipped in the repo is
`ServerSelector/myCA.pem`). Because the certificate is only valid for the
CDN hostnames in its SAN list (`*.nikke-kr.com`, `*.intlgame.com`, ...), the
game must connect to the hostname, not to a bare IP.

Two things are needed:

1. **Resolve `cloud.nikke-kr.com` to the local server for the game process
   only.** Use the resolver shim in `tools/wine-shims/cloudredirect.c`; it
   overrides `getaddrinfo`/`gethostbyname` under `LD_PRELOAD`. No `/etc/hosts`
   change is involved. If the server is not on the same machine, change
   `LOOPBACK` in the source to the server's IP.
2. **Make the prefix trust the CA.** Wine's wininet validates the chain, so an
   untrusted CA fails with `0x800c0019` even though the hostname matches.

Build the shims:

```bash
./tools/wine-shims/build.sh
```

Wine does not persist certificates added at runtime through `cert32`, so write
the serialized certificate blob into the registry while the prefix is stopped.
`tools/trust-epinelps-ca.py` generates the `.reg` file:

```bash
# CA that signed site.pfx (empty password):
openssl pkcs12 -in EpinelPS/site.pfx -nokeys -cacerts -passin pass: -out ca.pem

python3 tools/trust-epinelps-ca.py ca.pem > epinelps-ca.reg

WINEPREFIX=/path/to/prefix wineserver -k
WINEPREFIX=/path/to/prefix wine reg import epinelps-ca.reg
```

For reference, the CA shipped with this repo's `site.pfx` has the SHA-1
thumbprint `F11DE199323026C178501575EC02B5343FC2025E`; the resulting key is

```
HKEY_LOCAL_MACHINE\Software\Microsoft\SystemCertificates\Root\Certificates\F11DE199323026C178501575EC02B5343FC2025E
```

The script prints the thumbprint it used on stderr. To check a prefix has the
CA, use `certutil -store Root` under Wine (the probe in `tools/mfprobe/` is the
real end-to-end check).

Launch the game with the shim in the environment so it reaches the launcher and
the game processes:

```bash
LD_PRELOAD="$PWD/tools/wine-shims/libcloudredirect.so" ./your-launcher
```

If the game is started some other way (desktop file, AppImage, a launcher
script that resets the environment), set `LD_PRELOAD` there or the shim will
not be active.

## 4. Cache the media

The server serves `/media/<name>` from `server/cache/media`, and downloads a
file from the CDN once if it is missing. Every cutscene URL referenced by
`StaticData.pack` should be warmed ahead of time (268 URLs: 79 videos and 189
subtitles across all languages), otherwise an offline session gets a 404 and a
black video.

Warm the cache by requesting each file through the running server (the server
does the download), for example by extracting the URLs from the decrypted
static-data pack and looping over them with `curl -k`. Already-cached files are
cheap. This repository does not ship the media or a downloader; the server's
cache directory is part of your installation, not the source tree.

## 5. Optional: simulate offline play

`tools/wine-shims/offline-net.c` blocks every non-loopback `connect()` in the
game process tree (the launcher process itself is exempted by name), so
cutscene playback can be tested as if there were no internet. It is not needed
for normal play. Stack it with the resolver shim:

```bash
LD_PRELOAD="$PWD/tools/wine-shims/libcloudredirect.so:$PWD/tools/wine-shims/libofflinenet.so" \
  ./your-launcher
```

## Caveats

- Do **not** add `cloud.nikke-kr.com` to `/etc/hosts` without also trusting the
  CA: TLS validation fails with `0x800c0019` and every video breaks.
- Only H.264/AAC MP4 playback was verified. `WindowsVideoMedia error unhandled
  Color Standard: 0` is harmless noise and appears even on success.
- The certificate must be valid for the hostname being requested. The shipped
  `site.pfx` covers the CN/SAN list from `generate_ssl_cert.sh`; if you
  regenerate certificates, update the trusted CA blob too.
- `site.pfx` is a test certificate. Do not reuse it for anything real.
- This guide is about Wine/Media Foundation. The server-side `ch01_end_ja`
  redirect in this repository's history is unrelated to it and can be dropped.

## Building the probe

`tools/mfprobe/mfprobe.c` is a Winelib program that calls the same Media
Foundation APIs Unity uses:

```bash
/path/to/wine-11.22/bin/winegcc -municode -o tools/mfprobe/mfprobe.exe \
  tools/mfprobe/mfprobe.c -lmfplat -lmfreadwrite -lole32
```

Run it with the prefix and Wine you intend to use:

```bash
WINEPREFIX=/path/to/prefix WINELOADER=/path/to/wine \
  wine tools/mfprobe/mfprobe.exe https://cloud.nikke-kr.com/media/ch01_end_en.mp4
```

Expected: `MFCreateSourceReaderFromURL: 0x0`, a native subtype, and
`ReadSample: 0x0 ... len=<non-zero>`.
